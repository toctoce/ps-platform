# 백준 문제 검수

## 개요

BOJ 기반 문제 JSON이 실제 문제 조건을 제대로 반영하는지 검수한다. BOJ 원문을 그대로 복사하지 않고, 확인한 조건을 바탕으로 PS Platform용 한국어 문제로 다시 정리한다.

이 스킬은 출처 대조 절차만 다룬다. JSON 형식, 설명 품질, 예제 설명, 테스트 다양성, 카테고리 같은 내부 품질 검수는 `problem-reviewer` 기준도 함께 적용한다.

## 필수 참고 파일

검수 전에 저장소 루트에서 다음 파일을 읽는다.

- `.codex/skills/problem-reviewer/SKILL.md`
- `harness/problem-template.json`
- `docs/problem-categories.md`
- `docs/problem-authoring-guidelines.md`
- 대상 문제 JSON

## 출처 확인 원칙

- 실제 공개 출처와 대조하기 전에는 원문과 일치한다고 말하지 않는다.
- BOJ와 solved.ac는 직접 조회하지 않는다. 사용자가 다시 사용 가능하다고 명시하기 전까지 사용할 수 없는 출처로 간주한다.
- BOJ 페이지의 Web Archive 스냅샷을 우선 사용한다.
- Web Archive가 없거나 부족하면 입력, 출력, 제한, 예제, 핵심 규칙을 확인할 수 있는 풀이 블로그, 아카이브 요약, 공개 풀이 글, 공개 코드 저장소를 사용한다.
- 기억, 제목, 문제 번호, 유명 알고리즘 패턴만으로 판단하지 않는다.
- 출처 확인에 실패하면 그 사실을 명확히 말하고, 확인된 수정과 추정한 부분을 분리해서 보고한다.
- 원문 문장을 그대로 복사하지 않는다. 확인한 조건만 반영해 플랫폼용 한국어 설명으로 다시 작성한다.

## 대조 절차

1. 요청에서 BOJ 번호, 제목, 대상 JSON 파일을 확인한다.
2. Web Archive 또는 신뢰 가능한 대체 출처에서 실제 문제 조건을 찾는다.
3. 제목, 입력 형식, 출력 형식, 제한, 예제, 불가능한 경우, 정렬 기준, 여러 답 처리, 시간/메모리 제한을 확인한다.
4. 대상 JSON이 실제 조건을 유지하는지 비교한다.
5. 플랫폼용으로 바꾼 입력/출력 형식이 있다면 설명, 예제, 테스트, 풀이 전체에 일관되게 반영한다.
6. 실제 조건과 다르거나 근거가 약한 부분을 수정하거나 사용자에게 보고한다.
7. 수정한 JSON은 `problem-reviewer`의 검수 절차에 따라 다시 검증한다.

## 보고 기준

최종 응답에는 다음 내용을 포함한다.

- 사용한 출처 종류와 확인한 조건
- 실제 BOJ 조건과 다른 부분
- 플랫폼용으로 의도적으로 바꾼 부분
- 확인하지 못한 조건이나 남은 위험
- `problem-reviewer` 기준으로 수행한 JSON 검증 결과
