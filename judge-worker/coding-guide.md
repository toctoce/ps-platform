# Judge Worker Coding Guide

## 목적

`judge-worker`는 제출 코드를 안전하게 실행하고, 판정 결과를 `submission`에 반영하는 채점 서비스입니다.  
이 가이드는 아래 3가지를 일관되게 맞추기 위한 기준입니다.

- 정확한 채점 동작(컴파일/런타임/시간초과/메모리 제한/채점 결과)
- 예측 가능한 실패 처리
- 유지보수 가능한 테스트 구조

## 범위

`judge-worker` 모듈 전체에 적용합니다.

`judge-worker/internal` 아래의 실제 동작 코드(backend client, sandbox executor, evaluator, worker)와
main 패키지 진입점에 대한 규칙을 포함합니다.

## 테스트 기준

### 기본 원칙

1. 새 동작이 생기면 그 동작의 성공/실패 경로를 모두 테스트한다.
2. 외부 시스템 의존성은 **fake/stub**으로 격리한다.
3. 컨텍스트/시간/동시성 관련 코드는 타이밍 의존성을 최소화한다.
4. `gofmt`와 `go test ./...`은 커밋 전 필수다.

### 최소 테스트 범위 (의무 항목)

- 핵심 분기 100% 커버(적어도 아래는 필수)
  - `client.NextJob`이 `nil`을 반환하는 경우
  - `client.NextJob`이 에러를 반환하는 경우
  - `executor.Execute`가 각 verdict를 반환하는 경우
  - `client.CompleteJob` 실패 시 처리
  - 비정상 입력/빈 입력 처리
- `worker` 패키지
  - job이 여러 개 있을 때 백투백 처리되는지
  - job이 없으면 대기 루프로 빠지는지
  - 종료 시그널에 정상 반응하는지
- `evaluator` 패키지
  - 정답/오답 경계 케이스
  - 라인/공백 정규화 규칙이 의도대로 동작하는지
- `sandbox` 패키지
  - verdict 매핑을 실제 실행 결과로부터 정확히 산출하는지
  - 지원 언어별 실행 결과의 실패 구분 방식(추후 추가 시) 테스트

### 테스트 작성 규칙

- 기본 형태는 table-driven 테스트를 우선한다.
- 실패 경로는 `err`만 기대하지 말고 상태/메시지도 확인한다.
- 테스트는 비결정적 동작을 피하고, 시간 기반 판정은 명시적으로 마감 시간과 타임아웃을 고정한다.
- `t.Helper()`와 `t.Parallel()`은 의미가 있는 경우에만 사용한다.
- 한 테스트에 너무 많은 시나리오를 넣지 않고, 시나리오별로 분리한다.

### 실행 명령

- `cd judge-worker && go test ./...`
- `cd judge-worker && go test ./internal/...` (패키지 단위 반복 실행 시)
- `cd judge-worker && go test -race ./...` (동시성 변경이 있는 PR에서 권장)

## 주석 규칙

`go doc` 대상이 아닌 내부 주석은 필요한 이유를 설명할 때만 사용한다.

### 필수 주석

- `exported` 타입/함수는 모두 doc comment를 둔다.
- package 경계를 넘는 계약(예: 인터페이스, JSON 필드, 반환값 의미)은 주석으로 명시한다.
- 외부 API 또는 backend contract 변경은 주석으로 버전/호환성 전제를 적는다.

### 금지/지양 주석

- “무슨 동작인지 설명”만 반복하는 주석은 금지.
- 코드를 지우면 그대로 이해 가능한 주석은 지양.
- 구현 변경 이력을 적는 주석은 금지(커밋 메시지/PR로 관리).

### 좋은 주석 예시

- `왜` 이 코드가 필요한지 설명:
  - “큐가 비면 즉시 대기하는 것이 아니라 다음 폴링까지 기다리는 이유”
  - “컴파일 실패를 런타임 에러로 바꿔선 안 되는 이유”
- “불변식” 설명:
  - “한 번의 job은 `next -> execute -> complete` 순서를 벗어나지 않는다.”

## 명명/구조 가이드

- 외부 시스템 호출은 interface로 분리한다 (`backend.Client`, `sandbox.Executor` 패턴).
- 에러는 원인별로 구분 가능한 문자열/상태로 반영한다(`ACCEPTED`, `WRONG_ANSWER`, `COMPILE_ERROR`, `RUNTIME_ERROR`, `TIME_LIMIT_EXCEEDED`…).
- 숫자 상수(시간/재시도 횟수 등)는 하드코딩하지 말고 상수로 분리한다.
- 컨텍스트는 가능한 오래 전파하고, 작업 루프에서는 `ctx`를 무시한 블로킹 호출을 만들지 않는다.

## 커밋 전 체크리스트

- [ ] 변경 파일에 대해 `gofmt` 적용
- [ ] 해당 패키지 단위 테스트 100% 통과
- [ ] `go test ./...` 통과
- [ ] 예외/에러 경로 테스트가 추가 또는 유지됐는지 확인
- [ ] 주석은 “왜” 위주로 작성되었는지 확인
